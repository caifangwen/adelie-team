技术 SEO 审计很容易生成数百条问题，但问题数量不等于业务影响。对 B2B 网站而言，优先级取决于它是否阻止高价值页面被发现、理解和进入采购路径，而不是工具把它标成什么颜色。

## 第一步：确定重点页面

列出核心产品、服务、行业、应用、案例和询盘页，并记录自然流量、线索与销售价值。检查这些页面能否返回正确状态码、允许抓取、进入索引，并拥有自引用 canonical。一个核心产品页无法索引，比数百个无流量标签页标题重复更值得先处理。

同时确认站点地图只包含希望索引的规范 URL，robots.txt 没有误拦资源，页面也没有因模板或环境配置残留 noindex。

## 第二步：处理 URL 与重复内容

HTTP 与 HTTPS、带不带 www、大小写、参数和尾斜杠可能生成多个版本。选择一个规范形式，用重定向、canonical 和内部链接保持一致。改版时让旧 URL 单次 301 到最相关的新页面，不要全部跳到首页。

筛选、搜索和分页页面是否索引，要根据内容价值决定。技术规则必须支持页面策略，而不是为了让工具报告“零重复”一刀切。

## 第三步：让搜索引擎理解页面

每个重要页面需要清楚且独立的 title、H1、正文和内部链接文本。结构化数据只标记页面真实可见的信息，不能替代内容。JavaScript 渲染的网站还要检查主要内容和链接是否在搜索引擎可获取的 HTML 中。

## 第四步：修复性能与体验阻碍

优先检查真实用户常用设备上的核心页面：主图是否过大、布局是否跳动、交互是否延迟、第三方脚本是否阻塞。性能分数用于定位，不是最终目标。不要为了提高几分删除支持理解、信任或转化的必要内容。

## 如何排优先级

给每个问题记录受影响页面、业务价值、严重度、修复成本和依赖。通常顺序是：全站抓取与索引故障、核心页面错误、迁移和重复信号、内部链接与页面语义、性能体验，最后才是低价值模板细节。

## 修复后怎样验收

保存修改前的 URL、状态和数据基准；上线后重新抓取相关页面，检查源代码、canonical、索引状态和内部链接。随后观察抓取、展现、点击与有效线索。一次只集中修复一组相关问题，避免无法判断变化来源。

好的技术 SEO 不是永远修不完的清单，而是一套让重要内容稳定可访问、可理解、可维护的基础。

## 一个优先级示例

某制造业网站同时存在三类问题：新版产品目录被 noindex、博客图片缺少 alt、页脚出现几十条重复链接。第一项直接阻止商业页面进入搜索，应立即修复；重复页脚链接影响全站理解，可进入下一轮；图片 alt 只应优先补在产品与案例等真正需要替代说明的页面。按业务页面处理，比按工具告警数量处理更有效。

## 常见误区

不要在不了解原因时批量修改 canonical，也不要用 robots.txt 隐藏本应处理的重复 URL。工具无法抓取某个页面，不一定意味着搜索引擎也无法访问；反过来，工具显示“通过”也不代表页面具有索引价值。技术结论必须结合源代码、服务器响应、搜索平台数据和页面目的验证。
