网站改版会同时改变设计、内容、URL 和技术环境。流量下降时不要立刻重写全部内容，应先比较改版前后哪些页面、查询和目录失去表现，再检查对应变更。

## 先排除数据问题

确认 GA4、Search Console、同意管理和转化事件在上线后仍正常工作。分析代码丢失会表现为“流量归零”，但它和真实排名下降需要完全不同的处理。

## 检查抓取与索引

核对 robots.txt、noindex、canonical、站点地图和服务器状态码。测试旧 URL 是否通过单次 301 跳转到最相关的新页面；不要把全部旧地址重定向到首页。

## 比较页面信号

检查高流量页面的标题、H1、正文、内部链接和结构化数据是否被删除。新页面视觉更简洁，却可能失去搜索引擎和用户判断相关性所需的信息。

## 按损失价值修复

优先处理过去带来有效流量或询盘的页面。恢复内容、修正重定向并重新提交站点地图后持续观察抓取和展现，不要在同一时间继续大规模改动。

理想的迁移工作应在上线前完成 URL 映射、基准数据和回滚方案，而不是等流量下降后再补救。

## 如何定位损失页面

在 Search Console 比较改版前后至少四周的数据，按页面查看点击和展现变化，再按查询确认是排名下降、展示减少还是点击率变化。季节性明显的业务应同时参考去年同期。随后检查服务器日志或抓取数据，判断搜索引擎是否仍在访问旧地址。

如果损失集中在一个目录，通常优先检查模板、内部链接或目录级规则；如果全站同时下降，则更可能涉及 robots、noindex、域名、渲染或追踪。如果只有品牌查询下降，还要排查品牌需求和搜索结果展示变化。

## 修复后的预期

正确重定向和索引问题修复后，搜索引擎仍需要重新抓取和评估，不会立刻恢复。记录修复日期、受影响 URL 和抓取状态，每周观察即可。频繁更换重定向或重复提交会让判断更困难。

## 下一次迁移前留下什么

保存完整 URL 清单、自然流量基准、关键词表现、页面标题、重定向映射和上线检查记录。新旧站至少安排一次全量抓取，并让开发、SEO、内容和分析负责人共同签字确认关键项目。
