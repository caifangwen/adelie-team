## 02. 典型痛点

> 流程问题很少出在“没有系统”，而是系统之间的缝隙全靠人填。

- `审批靠微信群`：`采购、用印、请假在群里@领导，没有留痕、没有时效统计，事后审计翻聊天记录。`
- `跨系统重复录入`：`同一份订单信息要在 ERP、CRM、财务系统各录一遍，错漏率高，月底对账靠加班。`
- `例外比规则多`：`标准流程只覆盖六成情况，剩下四成靠老员工经验处理，人一休假流程就停。`
- `数据口径各说各话`：`业务、财务、仓库各有一套表格，月末报表靠人工拼接，数字永远对不齐。`
- `自动化买过但没落地`：`上过 BPM 或低代码平台，因为流程没梳理清就配置，最后沦为又一个需要手工维护的系统。`

## 03. 我们的做法

> 先梳理真实流程再写代码，自动化以“能验收的工时节省”为目标。

- `流程梳理与量化`：`现场跟岗记录每条流程的步骤、耗时与例外分支，输出流程热力图，按“年化工时 × 出错成本”排序优先级。`
- `规则引擎`：`把审批条件、额度分级、合规检查写成显式规则而非代码，业务人员可读可改，变更留痕可审计。`
- `RPA 机器人`：`对没有 API 的老系统用机器人完成录入、下载、对账，作为过渡期手段，并为后续接口化留好替换点。`
- `智能表单`：`用 OCR 与结构化抽取处理发票、合同、报关单，人工只做低置信度条目的复核。`
- `跨系统集成`：`通过 API 与消息队列打通 ERP、CRM、财务与自建系统，消灭重复录入，数据一次录入全程流转。`

## 04. 技术栈与工具

> 优先复用你已有的系统投资，新组件只补缺口。

- 配图：`https://images.unsplash.com/photo-1522071820081-009f0129c71c`
- `流程与规则`：`Camunda / Flowable 流程引擎、Drools 或自研 DSL 规则引擎，规则可视化、可版本化。`
- `RPA 与采集`：`UiPath / Power Automate 或 Playwright 自研机器人，按目标系统环境选型。`
- `表单与文档智能`：`OCR + LLM 结构化抽取管道，置信度路由到人工复核队列。`
- `集成层`：`REST / Webhook、Kafka 事件流、企业微信与钉钉消息通知接入现有办公入口。`
- `监控与度量`：`流程实例看板，实时统计平均处理时长、瓶颈节点与自动化覆盖率。`

## 05. 交付周期与节奏

> 以一条流程从诊断到上线 6–8 周为参照，滚动扩展到更多流程。

- `第 1 步 · 现场诊断（1–2 周）`：`跟岗记录真实流程，量化工时与出错成本，双方共同选定第一条自动化目标。`
- `第 2 步 · 流程重构（1 周）`：`先砍掉不必要环节、收敛例外分支，再决定哪些步骤交给机器。`
- `第 3 步 · 建设与联调（3–4 周）`：`规则引擎、表单与集成开发，用历史数据回放验证规则正确性。`
- `第 4 步 · 并行试运行（2 周）`：`新旧流程并行，人工结果与自动结果比对，差异清零后切换。`
- `第 5 步 · 运营与扩展（持续）`：`按看板数据调优，把已验证的模式复制到下一批流程，同时完成客户团队培训。`
- 节奏提示：`每次只并行推进 1–2 条流程，确保业务方有精力参与验收，避免一次性铺开失控。`

## 06. 结果与证据示例

> 以下为虚构示例，用于展示我们如何定义和呈现量化成果。

- `采购审批流程`：`某制造企业 12 级审批压缩为 4 级规则化审批，平均处理时长从 3.5 天降到 4 小时，全程留痕可审计。`
- `订单录入`：`跨三个系统的重复录入被集成层替代，单票录入时间从 25 分钟降到 0，错单率从 2.1% 降到 0.05%。`
- `发票处理`：`智能表单月处理 8,000 张发票，自动通过率 86%，财务复核人力从 3 人减到 1 人。`
- 注：`示例客户与数据仅用于内容结构演示，发布时替换为授权案例。`

## 08. 常见问题 FAQ

- `和直接买一套 BPM 或低代码平台有什么区别？`：`平台只是工具，失败通常发生在流程没梳理清就开始配置。我们先用 1–2 周跟岗梳理真实流程并量化收益，再决定用平台、自研还是两者结合，交付物是按工时节省验收的自动化流水线，而非一套没人用的系统。`
- `老系统没有 API，能做集成吗？`：`可以。过渡期用 RPA 机器人操作老系统界面完成数据流转，同时把每个机器人操作点记录为未来的接口需求；如果后续做遗留系统现代化，这些点位就是第一批要被真接口替换的清单。`
- `员工会抵触自动化吗？`：`我们的做法是自动化重复劳动、把例外判断留给人，并让一线员工参与流程重构的每一步——他们最清楚哪里浪费时间。验收口径是“把工时还给业务”，而不是裁减岗位。`
- `规则经常变，系统会不会很快过时？`：`规则写在规则引擎里而非代码里，业务人员经培训后可直接调整审批条件与阈值，变更留痕可回滚。移交阶段以你的团队独立完成一次规则变更作为验收。`
- `如何量化自动化值不值？`：`诊断阶段就会算清每条流程的年化工时与出错成本，优先级按这个数字排序；上线后用流程看板持续统计处理时长与自动化覆盖率，收益与当初测算的口径一致，可逐项对账。`
